# Руководство по развёртыванию клиента CSL Helpdesk (клиентская сторона)

Этот гайд описывает, как администратору развернуть приложение на всех ПК организации
через групповые политики (GPO) и как работает автообновление.

---

## 0. Что нужно (требования)

- Домен Active Directory и право создавать/редактировать GPO.
- Доступ к `h.csl.by` (Jira Server) с ПК пользователей (HTTPS/443).
- Доступ к `github.com` (или к зеркалу/корпоративному хранилищу) для автообновления.
  Для **приватного** репозитория — токен только на чтение (см. раздел 7).
- На клиентах: Windows 10/11. Python **не требуется** (EXE самодостаточный).
- Микрофон — опционально (для голосового комментария).

---

## 1. Подготовка доступа к Jira (один раз)

1. В `h.csl.by` создайте **сервисный аккаунт** (например, `svc-helpdesk`).
2. Дайте ему право **только создавать заявки** в проекте техподдержки
   (принцип наименьших прав — критично для безопасности общего логина).
3. Запомните логин и пароль — они пойдут в общий конфиг.

---

## 2. Получение EXE

EXE собирается автоматически GitHub Actions при каждом пуше в ветку проекта.
Готовый файл `CSLHelpdesk.exe` лежит в **Releases** (актив `CSLHelpdesk.exe`)
или в артефактах последнего прогона Actions. Скачайте его.

Если нужно собрать вручную (на Windows с Python): `powershell -File deploy\build-exe.ps1`.

---

## 3. Заполнение административного конфига (один раз)

Возьмите `deploy/admin-config.json.template`, заполните и сохраните как `config.json`:

```json
{
  "jira_url": "https://h.csl.by",
  "api_user": "svc-helpdesk",
  "api_password": "ОБЩИЙ_ПАРОЛЬ",
  "project_key": "HELP",
  "issue_type": "Запрос",
  "verify_ssl": true,
  "faults": ["Не работает интернет / сеть", "Медленно работает", "..."],
  "github_repo": "zigorminsk-debug/client.help",
  "github_token": "",
  "update_enabled": true
}
```

Поля:
- `jira_url` / `api_user` / `api_password` / `project_key` / `issue_type` — доступ к Jira.
- `faults` — список чекбоксов неисправностей (можно менять без пересборки EXE).
- `github_repo` — `owner/repo` для автообновления. Если пусто — обновления отключены.
- `github_token` — токен только на чтение (для приватного репозитория). Для публичного —
  можно оставить пустым (но действует лимит 60 запросов/час на IP).
- `update_enabled` — `false`, чтобы отключить автообновление принудительно.

> ⚠️ `config.json` содержит ОБЩИЙ пароль. Не коммитьте его в Git и не давайте
> пользователям прав на запись в папку, куда он копируется (ProgramData).

---

## 4. Размещение файлов на сетевом ресурсе

Положите `CSLHelpdesk.exe` и `config.json` в каталог на SYSVOL/GPO-шаре, например:
`\\ВАШ_ДОМЕН\sysvol\ВАШ_ДОМЕН\Policies\{GPO-GUID}\Helpdesk\`

Путь до этой папки понадобится в GPO-скрипте (параметр `-SourceShare`).

---

## 4.1. Развёртывание через MSI (WiX) — рекомендуется

Готовый `CSLHelpdesk.msi` собирается автоматически CI вместе с EXE и выкладывается
в релиз (актив `CSLHelpdesk.msi`). Либо соберите локально: `powershell -File deploy\build-all.ps1`.

**Важная особенность:** MSI устанавливает **пер-пользовательски** в
`%LocalAppData%\CSL\HelpdeskClient` (НЕ в ProgramData), поэтому:
- установка через GPO не требует прав администратора;
- приложение может **самообновляться** (заменять свой EXE) без UAC-запроса.

Способы развёртывания MSI через GPO:
- **A) User Configuration → Policies → Software Installation → Publish** (или Assign).
  Пользователи получают приложение при входе; ярлык появляется в меню Пуск и на Рабочем столе.
- **Б) Logon-скрипт:** `msiexec /i \\SHARE\CSLHelpdesk.msi /qn /norestart`

Общий конфиг (единый логин Jira) MSI кладёт рядом с EXE; при необходимости админ
перекрывает его через GPO Preferences (реестр `HKLM\SOFTWARE\CSL\Helpdesk`) или файл в
ProgramData — они имеют приоритет (см. `src/config.py`, `_config_candidate_paths`).

Переустановка/обновление: в WiX настроен `MajorUpgrade` — при установке MSI с бо́льшей
версией предыдущая per-user-версия удаляется автоматически.

## 5. Настройка GPO (логон-скрипт)

1. **Group Policy Management** → создайте/выберите GPO, привяжите к нужному OU
   (туда, где пользователи).
2. **User Configuration → Policies → Windows Settings → Scripts (Logon)**.
3. Добавьте `deploy/Install-HelpdeskClient.ps1`.
   В параметрах укажите `-SourceShare "\\ВАШ_ДОМЕН\sysvol\...\Helpdesk"`.
4. (Опционально) **User Configuration → Policies → Windows Settings → Scripts (Logoff)**
   → `deploy/Uninstall-HelpdeskClient.ps1` для корректного снятия при выходе.

Что делает скрипт при входе пользователя:
- копирует `config.json` в `C:\ProgramData\CSL\HelpdeskClient\` (читается приложением);
- копирует `CSLHelpdesk.exe` в `%LOCALAPPDATA%\CSL\HelpdeskClient\` (профиль
  пользователя — отсюда приложение самообновляется без прав администратора);
- создаёт ярлык **«CSL Helpdesk» на Рабочем столе и в меню Пуск** пользователя.

5. На клиентах: `gpupdate /force` (или выход/вход). У пользователя появляется ярлык.

> Альтернатива реестру/файлу — GPO Preferences → Registry:
> `HKLM\SOFTWARE\CSL\Helpdesk` с параметрами `JiraUrl`, `ApiUser`, `ApiPassword`,
> `ProjectKey`, `IssueType`, `VerifySsl`, `Faults` (`;` — разделитель), `GithubRepo`.
> Приложение читает и оттуда.

---

## 6. Проверка работы

1. Войдите под обычным пользователем, запустите ярлык.
2. Первый запуск попросит **контактный телефон** — введите, он сохранится.
3. Отметьте неисправность, добавьте скриншот/комментарий, нажмите **«Отправить заявку»**.
4. В `h.csl.by` должна появиться заявка с описанием, системной информацией и вложениями.
5. Проверьте автообновление: в меню нажмите **«Проверить обновления»** (или подождите
   автопроверку при старте). Если доступна новая версия — кнопка превратится в
   **«Обновить до vN»**; по нажатию EXE заменится и перезапустится.

---

## 7. Автообновление из GitHub

- При каждом пуше в ветку проекта CI собирает EXE и создаёт **Release `vN`**
  (порядковый номер = число релизов + 1).
- Клиент при старте (через ~2.5 с) сверяет свой `APP_VERSION` с последним релизом
  (`GET /repos/{repo}/releases/latest`). Если релиз новее — предлагает обновление.
- Новый EXE скачивается во временный файл, вспомогательный `.bat` переименовывает
  текущий и заменяет его, затем перезапускает приложение. Файл лежит в профиле
  пользователя (`LocalAppData`), поэтому замена не требует прав администратора.

**Приватный репозиторий:** укажите в `config.json` `github_token` — fine-grained
токен с единственным правом `Contents: read`. Без токена публичный репозиторий
работает в рамках лимита 60 запросов/час на IP (у большой организации может
исчерпаться — тогда используйте токен или внутреннее зеркало).

---

## 8. Безопасность единого логина

Поскольку приложение работает от обычного пользователя, оно должно читать общий
пароль → любой локальный пользователь технически может его извлечь (ProgramData/реестр).
Снижение риска (обязательно):
- Используйте **только сервисный аккаунт Jira с правом создавать заявки**; никаких
  широких прав.
- Не используйте учётку реального администратора.
- Держите `config.json` доступным на чтение `Authenticated Users` (запрет чтения
  сломает работу приложения — это ограничение самой модели «один логин на все ПК»).

Продвинутый вариант (опционально): вместо хранения пароля на клиентах поднимите
внутренний «брокер», который держит учётные данные Jira и принимает от клиента только
собранные данные заявки. Клиент тогда секрет не хранит.

---

## 9. Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| Нет ярлыка у пользователя | GPO-логон-скрипт не применился → `gpupdate /force`, проверьте права на `-SourceShare` (чтение для `Authenticated Users`) |
| «Не настроена групповая политика» при запуске | `config.json` не скопирован в ProgramData или пусты `jira_url`/`api_user`/`project_key` |
| Ошибка 401 при отправке | неверный `api_user`/`api_password` или нет прав создавать заявки |
| Кнопка «Записать голос» неактивна | нет микрофона / не установлен PortAudio (sounddevice) в сборке |
| Автообновление не предлагается | не задан `github_repo` в конфиге, или `APP_VERSION=0` при локальном запуске из исходников |
| Обновление не заменяет EXE | EXE запущен не из `LocalAppData` (а из ProgramData/общего расположения, куда user не может писать) — перераскатайте через логон-скрипт |
| Частые «rate limit» при проверке обновлений | приватный репозиторий без `github_token`, либо много ПК за одним NAT — добавьте токен |

---

## 10. Снятие (Uninstall)

Назначьте `deploy/Uninstall-HelpdeskClient.ps1` как Logoff-скрипт, либо запустите
вручную от пользователя — удалит ярлыки и локальную копию EXE. Общий конфиг в
ProgramData удаляется отдельно (требует прав администратора).
